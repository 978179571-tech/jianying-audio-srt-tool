# 配音与字幕整理

Windows 桌面工具：读取剪映草稿中的独立朗读配音，按逐行文案重新排列，清理每段首尾多余静音，输出配音 WAV 与连续显示的 SRT。

## 下载使用

在 [程序下载页面（Releases）](https://github.com/978179571-tech/jianying-audio-srt-tool/releases/latest) 的 **Assets** 中下载 `jianying-audio-srt-tool-v1.1-windows-x64.zip`，解压后双击 `配音字幕整理-v1.1.exe`。不需要安装 Python 或 .NET。

如果只想使用程序，下载上面的 Windows 压缩包即可；`Source code (zip)` 是源码，不是可直接运行的程序。

音频处理需要本机提供 `ffmpeg.exe`。程序会尝试寻找剪映安装目录或 PATH 中的 FFmpeg；找不到时在“设置”中手动选择。下载包未附带 FFmpeg。

## 使用指南

### 第一步：准备剪映草稿

在剪映中准备好文案，并通过“朗读”功能生成配音，等待草稿保存完成。

请保留一段段可以单独拖动的朗读音频。即使它们分布在不同音轨、相互重叠、句间空白太长，也可以由本工具重新排列。仅有一条已经混合导出的音频时，无法恢复里面重叠的声音。

找到这个项目的**单个草稿文件夹**，确认其中有 `draft_content.json`。可以通过剪映显示的草稿保存位置查找；文件夹结构通常类似：

```text
某个剪映草稿/
├── draft_content.json
├── textReading/          原始朗读音频（可能存在）
├── subdraft/             复合片段（可能存在）
└── Timelines/            时间线数据（可能存在）
```

选择具体项目这一层，不要选择包含许多项目的草稿总目录。

### 第二步：选择草稿和配音组

1. 打开工具，点击 **选择剪映草稿**，选择刚才的项目文件夹。
2. 等待读取完成，核对顶部“配音组”显示的段数和开头文字。
3. 如果发现多个配音组，在下拉框中选择本次要整理的一组。

主草稿部分数据无法直接读取时，工具可能找到可读的复合片段。这时要核对文案是否属于当前版本，不能只看“读取成功”就直接导出。

### 第三步：输入你想要的字幕分行

在左侧 **逐行文案** 中粘贴文案，或点击 **导入 TXT**。不准备另外的文案时，也可以点击 **用草稿文案**，再修改换行。

**每一行就是一条最终字幕。** 例如原来有下面三段独立配音：

```text
欢迎使用
配音与字幕整理
现在开始
```

希望前两段声音接成一句、显示成一条字幕，就输入：

```text
欢迎使用配音与字幕整理
现在开始
```

文案的文字和顺序需与配音一致，只调整换行。需要无标点时，点击 **去掉标点**，再核对一次。D3 / D₃ 等兼容字符可以匹配，导出时保留你输入的写法。

点击 **按这份文案匹配配音 →**。右侧出现逐句列表，就可以继续生成试听。文字不一致或分行落在一段配音内部时，工具会提示具体问题。

### 第四步：生成试听并调整停顿

点击 **生成 / 更新试听**。程序会裁掉每个原始朗读片段首尾的多余静音，按文案顺序拼接，并保留片段内部的停顿与呼吸声。

生成后，可以用下面的按钮检查：

| 按钮 | 用途 |
| --- | --- |
| 整段试听 | 从头听完整配音，字幕预览随声音切换 |
| 选中句 | 听表格中选中的一句，也可以双击该行 |
| 两句衔接 | 听选中句与下一句之间的连接和停顿 |
| 停止 | 停止播放；正在生成时也可停止任务 |

**统一调整所有句子的句后停顿：**

1. 点击右上方 **全选 (Ctrl+A)**，或先点击右侧句子列表，再按 **Ctrl+A**。
2. 在“句后停顿”中填入数值，例如 `200` 毫秒就是 `0.2` 秒。
3. 点击 **应用到选中句**。
4. 点击 **生成 / 更新试听**，试听满意后再导出。

只想改其中几句时，用 Ctrl 点击多选，或用 Shift 选择连续几行。只修改停顿时，各句原有语速会保留；只修改语速时，各句原有停顿会保留。

| 可调项目 | 范围与含义 |
| --- | --- |
| 句后停顿 | 0～3000 毫秒，决定这一行与下一行之间额外加入的空白；最后一句不加尾停顿 |
| 语速 | 0.75～1.50 倍，默认 1.00 倍 |
| 同行接缝停顿 | 在“设置”中调整，0～1000 毫秒，默认 80；用于同一行由多段配音接成的情况 |
| 恢复自然停顿 | 恢复规则生成的各行句后停顿，保留当前语速设置 |

句后停顿设为 0 表示不额外插入静音，并不删除片段内部停顿或声音边缘保留的余量。默认节奏是可调整的起点，具体以试听效果为准。

### 第五步：导出并放回剪映

点击 **导出 WAV + 连续字幕**，选择保存位置。工具会自动新建一个结果文件夹，包含：

| 文件 | 用途 |
| --- | --- |
| `配音.wav` | 整理好的完整配音 |
| `字幕-连续显示.srt` | 按你的分行生成、条目之间无空档的字幕 |
| `逐行文案.txt` | 保存本次文案 |
| `处理记录.json` | 保存音频来源、停顿、语速和时间，方便核对 |

建议先在剪映的新草稿中测试：

1. 通过 **素材 → 导入** 加入 `配音.wav`，拖到时间线，左边缘对齐 **00:00**。
2. 通过 **文本 → 新建文本 → 导入本地字幕** 加入 `字幕-连续显示.srt`。不同剪映版本的入口名称可能略有差异。
3. 从头播放，检查配音与字幕切换。**无需再对字幕执行“朗读”。**

若放回原项目，要停用原来的朗读配音和旧字幕，避免与新文件重复播放或重叠显示。整理后的音频可能比原视频长，需要相应调整画面长度。

**无断档指的是字幕连续显示：上一条结束时间等于下一条开始时间。声音仍可以保留你设置的自然停顿。**

### 下次继续调整

点击 **保存方案** 可以保存草稿位置、配音组、文案分行、每句停顿和语速。下次用 **打开方案** 继续，再生成试听与导出。

方案文件不包含配音素材；需要保留原草稿与音频。草稿内容变化或文件夹移动后，请根据提示重新选择并核对。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 没有找到可读取的独立朗读配音 | 确认选择的是单个草稿，且配音仍是独立片段。可尝试在剪映中把本次字幕和朗读配音组成复合片段、保存后再读取；不同版本不保证有效 |
| 提示“文案与配音文字不一致” | 按提示检查错字、缺字、数字读法和顺序；可以先用“用草稿文案”重新载入，再只修改换行 |
| 提示换行落在配音内部 | 本版只支持合并完整配音片段。需先在剪映里按新的分行生成独立朗读，再读取草稿 |
| 找不到 FFmpeg 或音频工具无法运行 | 打开“设置”，选择剪映安装目录中的 `ffmpeg.exe`；若没有，需自行准备可用的 FFmpeg，下载包没有附带它 |
| 修改了停顿，但试听没有变化 | 确认先选择了句子，再点击“应用到选中句”，最后点击“生成 / 更新试听” |
| Ctrl+A 没有选中全部句子 | 先点击右侧句子列表，或直接用“全选 (Ctrl+A)”按钮；左侧文案框中的 Ctrl+A 只全选文字 |
| 导出后仍听到两段声音同时播放 | 检查剪映里原来的朗读音轨是否仍在播放，新配音应单独使用并从零秒开始 |

## 功能

- 使用现有音色；默认保留原始语速。
- 按文案顺序消除片段之间的重叠。
- 仅清理每段音频首尾静音，保留片段内部停顿与呼吸声。
- 按文案分行合并完整朗读片段，输出保留输入文字。
- 句间停顿可设为 0～3000 毫秒；同一行内多个音频的接缝停顿可调整。
- 各行语速支持 0.75～1.50 倍。
- 支持“全选”按钮、Ctrl+A、多选批量调整；只改变停顿时保留各行语速。
- 字幕从零秒开始，上一条结束时间等于下一条开始时间，中间无断档。
- 保存及恢复整理方案，每次导出新建文件夹。
- 本地处理，原草稿和原始音频保持不变。

## 兼容范围与限制

- 支持可读取的剪映 JSON 中的独立“文本朗读”音频，包括复合片段内嵌数据。
- 不解密主草稿，不读取 `.bak` 备份。主稿加密但有可读复合片段时，需要核对该组内容是否为本次使用的版本。
- 支持多个完整音频片段合为一行；换行落在一个片段内部时会提示先拆分朗读，不会按字数猜切点。
- 不恢复已经混合在同一音频中的重叠语音，不自动去除句内呼吸声。
- 文案需与配音文字和顺序一致。可兼容 D3 / D₃ 等字符写法，无法自动修正文案与实际朗读内容的差异。
- 整理后总时长随配音变化，不保证与原视频长度一致。

完整操作说明见 [使用说明.md](使用说明.md)，通用示例见 [examples/script.txt](examples/script.txt)。

## 从源码运行

Windows，Python 3.10+（包含 Tkinter）。运行时 Python 代码仅使用标准库，另需本地 FFmpeg。

```powershell
python app.py
```

## 测试

```powershell
python -m unittest -v test_engine test_app
```

可选真实草稿集成测试：设置 `CCJ_TEST_DRAFT` 为草稿文件夹，`CCJ_TEST_SCRIPT` 为与其匹配的逐行 TXT 文案。测试会在临时文件夹生成结果，所有输入保留在本机。

## 打包 Windows 程序

```powershell
python -m pip install -r requirements-build.txt
.\build.ps1
```

程序生成于 `dist`，构建依赖与第三方 FFmpeg 均不提交到源码仓库。

本仓库不包含实际业务草稿、配音素材、个人方案和本机设置。
